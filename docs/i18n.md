# Sprachen der Mitarbeiter-Oberfläche (Prompt K1)

Gäste-Screen hat eine eigene i18n (`src/lib/guestI18n/`) und ist hiervon nicht betroffen.

## Wer sieht welche Sprache?
1. `User.language` (am Nutzer, gilt auf jedem Gerät) — gewählt über den Sprach-Knopf (Kopfzeile; mobil im Meldungs-Panel; Login-Seite).
2. sonst zuletzt auf dem Gerät gewählt (localStorage), sonst `Setting hotelDefaultLanguage` (Einstellungen → Hotel-Standardsprache).
3. Hat jemand nie gewählt, schlägt die App nach dem Login die Browser-Sprache vor (nur Vorschlag, wird erst mit Klick gespeichert).

Wechsel wirkt sofort (kein Neuladen): `LocaleProvider` lädt die Texte nach und setzt `<html lang dir>`.

## Drei Stufen
| Stufe | Sprachen | Quelle | Kennzeichnung |
|---|---|---|---|
| Quelle | Deutsch (Quellsprache), Englisch (vollständig) | `src/lib/i18n/translations.ts` (typgeprüft) | — |
| Priorität | vi, it, tr, fa, hi | `src/lib/i18n/locales/<code>.json` (versioniert) | „Nicht muttersprachlich geprüft“, bis `_meta.reviewed` |
| Laufzeit | alle anderen | `/api/i18n/<code>` → `TranslationProvider`, Cache `UiTranslation` | „Maschinell übersetzt“ |

Rückfall immer: Sprache → Englisch → Deutsch. Fehlende Schlüssel meldet `onMissingKey` (Entwicklerkonsole) und
`tests/i18n/completeness.test.ts` (rot bei fehlenden/veralteten Schlüsseln oder falschen Platzhaltern).

Umfang der Prioritätsdateien: **Teil 1** (`src/lib/i18n/coverage.ts`): Housekeeper, Hausmann, Technik, gemeinsame Teile
(Kopfzeile, Status, Meldungen, Fehler, Chat). Supervisor-Werkzeuge, Duty Manager, Front Office, Concierge, Planungstool,
Import zeigen in diesen Sprachen noch Englisch (Teil 2).

## Muttersprachler-Korrektur
```
npm run i18n:review -- vi            # i18n-review-vi.tsv: Schlüssel | Deutsch | Englisch | Übersetzung | geprüft
# Spalte „Übersetzung“ korrigieren (Tabellenkalkulation, als TSV speichern)
npm run i18n:import -- vi i18n-review-vi.tsv --reviewed "Name"
npm run i18n:missing                 # was fehlt noch je Sprache
```
Der Import erhöht `_meta.version` und trägt geprüfte Schlüssel in `_meta.reviewedKeys` ein.

## Fachglossar
`src/lib/i18n/glossary.ts`: feste Begriffe je Sprache. Bei Laufzeit-Übersetzung werden Begriffe und `{{platzhalter}}` vor
dem Anbieter durch Marker ersetzt und danach eingesetzt (geht ein Marker verloren → Text verworfen → Englisch).
`tests/i18n/glossary.test.ts` prüft auch, dass die Prioritätsdateien die Glossarbegriffe benutzen.

## Server-Texte
- Fehler: `{ error: "<Klartext>", code: "<CODE>" }`; der Client zeigt `errors.<CODE>` (`errorText()`), sonst den Klartext.
- Meldungen: `Notification.messageKey` + `messageVars` (`keyed()` aus `notificationText.ts`); `message` bleibt Klartext.
  Werte mit Namen auf `Key` (z. B. `roleKey`) übersetzt der Client mit. Nie Gastnamen in `messageVars`.

## Rechts-nach-links, Zahlen, Schriften
- `dirFor()` (fa, ar, he, ur …). Layout nur mit logischen Klassen (`ms-/me-/ps-/pe-/start-/end-/text-start/border-s`);
  `tests/i18n/rtl.test.ts` findet neue `ml-/mr-/left-/text-left`. Grundriss/Haus-Bild bleiben `dir="ltr"`.
- Datum/Zeit/Zahlen über `fmt`/`hhmm`/`dateTime` (`src/lib/i18n/format.ts`): lateinische Ziffern, gregorianischer
  Kalender, 24 h, Zeitzone Berlin. Zimmernummern/Etagen nie formatieren.
- Schriften: Inter/Cormorant mit latin-ext + vietnamese (+ kyrillisch/griechisch), Noto Sans Devanagari und Vazirmatn als
  Fallback (ohne Preload). Keine Buchstaben-Sperrung für verbundene Schriften (globals.css).

## Anbieter (vorbereitet für K2)
`src/lib/translation/provider.ts`: `TranslationProvider` + `registerTranslationProvider(id, factory)`; aktiv über
`TRANSLATION_PROVIDER=<id>` (Zugangsdaten nur als Umgebungsvariablen). Ohne Anbieter: Laufzeit-Sprachen zeigen Englisch.
K1 schickt nur Oberflächentexte (keine Personen-/Gastdaten).
